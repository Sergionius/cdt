# CDT 0.4.1: run safety and navigation

## Status

Implemented on 2026-07-28. The failure-gap audit confirmed existing coverage for resume artifacts, hook timeouts, stale PIDs, corrupt statuses, provider errors, and parallel interruption; targeted additions cover redaction, missing worker terminal status, multiple parallel failures, and run navigation.

## Objective

Improve persisted-log safety, recent-run navigation, and failure handling without adding external integrations or a permanent end-to-end demo project.

## Scope

### 1. Secret redaction and process smoke tests

Add a side-effect-free secret redactor that:

- discovers values from environment keys matching `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `PRIVATE_KEY`, `API_KEY`, `AUTH`, and `CREDENTIAL`;
- supports extra environment key names through `CDT_REDACT_KEYS`;
- ignores empty values and values shorter than four characters;
- replaces literal values longest-first and idempotently;
- conservatively redacts Bearer tokens, authorization headers, password assignments, and JWT-looking values;
- preserves ordinary Git SHAs and checksums.

Apply redaction to detached output before it is written to disk, status errors, worker startup failures, CDT-owned summaries, and `cdt logs`. Do not intercept inherited foreground output from third-party tools in this release.

Add focused subprocess smoke tests using temporary projects. Cover output split between chunks, a final line without a newline, worker startup failure, and the invariant that a known secret does not appear under `.cdt/runs/`. Do not add a permanent E2E fixture project.

### 2. Recent-run navigation

Support:

```bash
cdt status
cdt status <run-id>
cdt status --pipeline test
cdt logs
cdt logs <run-id>
cdt logs --pipeline test
cdt logs --tail 120
cdt history --pipeline test
cdt history --status failed
cdt history --status success --limit 10
cdt history --json
```

Resolution priority is explicit run ID, selected pipeline, then newest global run. History filters compose and are applied before the limit. Sorting remains newest-first and uses effective status, including exit-code precedence and stale process detection. Corrupt records must not prevent healthy records from being shown.

### 3. Failure hardening

Audit existing tests before adding coverage. Prioritize worker spawn/exit failures, missing exit metadata, corrupt status JSON, stale PIDs, atomic persistence failures, interrupted and multiply-failing parallel groups, command timeouts, missing resume artifacts, version-mutating retries, malformed provider responses, and cancellation semantics.

Every failure test should verify the terminal state, concise diagnostics, preservation of useful records, absence of persisted secrets, and ability to start a later run. Change production behavior only where a test demonstrates a real defect.

### 4. Documentation and release verification

Update `README.md`, `docs/runs.md`, `docs/getting-started.md`, `docs/ai-agents.md`, the bundled release skill, CLI help, and `CHANGELOG.md` together. Document that redaction is defense in depth and that run records may still contain project paths and artifact names.

## Non-goals

- Permanent E2E demo project.
- Automatic run retention or pruning.
- New upload providers or provider lifecycle features.
- `cdt explain`, structured outcomes, final release summaries, or `cdt run --detach`.
- Dashboard, MCP, database, or remote workers.

## Implementation order

1. Redactor and unit tests.
2. Detached streaming integration and subprocess smoke tests.
3. Status/log resolution and history filters.
4. Failure-gap audit and targeted hardening.
5. Documentation, changelog, package, and installed-wheel checks.

## Verification

Run after focused edits and before completion:

```bash
ruff check .
pytest -q
pytest --cov=cdt --cov-report=term
python -m build
twine check dist/*
```

Smoke-test the installed wheel command help for `status`, `logs`, and `history`.

## Acceptance criteria

- A known test secret never appears in detached logs or status errors.
- `status` and `logs` resolve a recent run without copying its ID.
- History supports composing pipeline and status filters before applying its limit.
- Corrupt run records do not break navigation across healthy records.
- Existing `cdt run <pipeline>` behavior remains compatible.
- All lint, test, coverage, build, metadata, and wheel smoke checks pass.
